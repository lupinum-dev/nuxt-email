---
title: Error types
description: Public error classes, their stable fields, common symptoms, and recovery steps.
---

Nuxt Email exposes two runtime error classes from `@lupinum/nuxt-email/errors`. Original render failures remain available through `cause`.

## Public errors

| Error | When it occurs | Stable fields | What to do |
| --- | --- | --- | --- |
| `EmailRenderError` | Loading, prop validation, Vue server rendering, `EEmail` validation, or plain-text conversion fails. | `templateName`; original failure on `cause` | Log the error and inspect `cause`. Fix the template, props, or document named by `templateName`. |
| `UnknownEmailTemplateError` | An untyped runtime name is absent from the generated registry. | `requestedName`; sorted `knownNames` | Use one of `knownNames`, or add the template and run `nuxt prepare`. |

`EmailRenderError.templateName` is the registry name passed to `renderEmail()`. There is no `componentName` compatibility alias.

## Find an error by symptom

The message of an `EmailRenderError` is always `Failed to render email template <name>`. The search phrases below are in `error.cause.message`.

| Search phrase or symptom | Error | Next check |
| --- | --- | --- |
| Template not found, unknown template, or unknown email | `UnknownEmailTemplateError` | Compare `requestedName` with `knownNames`. Nested names use `/` and omit `.vue`. |
| `must use EEmail as its root`, `exactly one EEmail`, or `nothing around it` | `EmailRenderError` | Make one `EEmail` the root of the template. |
| `EMarkdown takes its Markdown from the source prop` | `EmailRenderError` | Pass the Markdown string as `:source`; the default slot is not read. |
| `uses an unsafe URL scheme` | `EmailRenderError` | Use an `http`, `https`, `mailto`, `tel`, `cid` or relative URL in the `href` or `src` named in the message. |
| `Email props must be an object` or `Missing required email component prop` | `EmailRenderError` | Pass an object as props. A required prop set to `undefined` counts as missing. |
| `Unknown email component prop` | `EmailRenderError` | Remove the props that the template does not declare. |
| Render failed or invalid props | `EmailRenderError` | Inspect `error.cause`; it preserves the underlying failure. |

There is no `TemplateNotFoundError`. The public class for that condition is `UnknownEmailTemplateError`.

## Imports

```ts
import { EmailRenderError, UnknownEmailTemplateError } from '@lupinum/nuxt-email/errors'
```

`@lupinum/nuxt-email/testing` exports the same two classes.

## Build errors

The build stops with a plain error, not a public class, when a template cannot compile:

| Message contains | Next check |
| --- | --- |
| `Unknown email component` | Import the component in the template's script, or use a registered `E*` component. |
| `needs the nuxtEmail codeBlock module option` | Add the `codeBlock` module option, or remove `ECodeBlock`. |
| `@container rules are not supported` | Remove container query variants such as `@sm:`. |
| `module imports are not supported in email Tailwind CSS` | Replace `@plugin` or `@config` in `tailwind.css` with `@theme` and `@utility`. |
| `do not support style or custom blocks` | Remove the `<style>` or custom block from the file named in the message. Use Tailwind classes or inline styles. |
| `do not support external SFC blocks` | Remove the `src` attribute from the block in the file named in the message. Import local components instead. |
| `support JavaScript/TypeScript scripts and HTML templates only` | Remove the `lang` attribute, or set it to `ts` or `js`, in the file named in the message. |

These template rules apply in the Nuxt module, in `@lupinum/nuxt-email/build` and in `createTestRenderer()`. They apply to every `.vue` file that a template imports. Each message about a file contains its path. The Tailwind messages about `@container` rules and module imports do not.

Template discovery can report `EmailTemplateDiscoveryError` during module setup. These are diagnostics, not exports from the public error entry point.

## Production handling

Log the full error on the server, including `cause`. Return a generic response to the caller. Nuxt Email does not serialize filesystem paths or stacks into production responses. The [development preview]($docs/guides/preview-workflow) shows richer local details for authoring.

```ts [server/api/welcome.get.ts]
export default defineEventHandler(async () => {
  try {
    return await renderEmail('welcome', {
      name: 'Ada',
      actionUrl: 'https://example.com/dashboard',
    })
  }
  catch (error) {
    console.error(error)
    throw createError({ statusCode: 500, statusMessage: 'Email render failed' })
  }
})
```
