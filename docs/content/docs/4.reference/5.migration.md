## Upgrade from 1.0.0-beta.5

`1.0.0-beta.6` replaces the document wrappers with one `EEmail` root and resolves Tailwind classes at build time. A production render no longer loads Tailwind or a CSS parser.

The rendered HTML also changes without a template change. Sizes from Tailwind classes are written in `px`, at 16 px per `rem`. Colors are written as hex or `rgba()`, and leading zeros are dropped. Review snapshot tests of rendered HTML after the upgrade. Follow the steps below in order.

### Update Node.js

The minimum Node.js versions are now 22.22.3 on the Node 22 line and 24.15.0 on the Node 24 line. Node 26 needs no change.

### Before

```vue [app/emails/welcome.vue]
<script setup lang="ts">
import { defineEmail } from '@lupinum/nuxt-email/define-email'

const props = defineProps<{ name: string, actionUrl: string }>()

defineEmail({
  subject: () => `Welcome, ${props.name}`,
})
</script>

<template>
  <ETailwind>
    <EHtml lang="en">
      <EHead />
      <EBody class="bg-slate-100 p-6">
        <EPreview>Your account is ready.</EPreview>
        <EContainer class="rounded-lg bg-white p-8">
          <EHeading class="text-2xl font-semibold text-slate-900">Welcome, {{ name }}</EHeading>
          <EText class="text-slate-600">Your account is ready.</EText>
          <EButton :href="actionUrl" class="rounded-md bg-emerald-600 px-5 py-3 text-white">Open dashboard</EButton>
        </EContainer>
      </EBody>
    </EHtml>
  </ETailwind>
</template>
```

### After

```vue [app/emails/welcome.vue]
<script setup lang="ts">
defineProps<{ name: string, actionUrl: string }>()
</script>

<template>
  <EEmail :subject="`Welcome, ${name}`" lang="en" preview="Your account is ready." class="bg-slate-100 p-6">
    <EContainer class="rounded-lg bg-white p-8">
      <EHeading class="text-2xl font-semibold text-slate-900">Welcome, {{ name }}</EHeading>
      <EText class="text-slate-600">Your account is ready.</EText>
      <EButton :href="actionUrl" class="rounded-md bg-emerald-600 px-5 py-3 text-white">Open dashboard</EButton>
    </EContainer>
  </EEmail>
</template>
```

### Replace the document wrappers with EEmail

Replace `EHtml`, `EHead`, `EBody`, and `EPreview` with one `EEmail` root:

- Move `lang` and `dir` from `EHtml` to `EEmail`.
- Move the `EPreview` text to the `preview` prop.
- Move `EHead` content, such as `<title>` or `EFont`, to `<template #head>`.
- Move the body `class` and `style` to `EEmail`.

### Replace defineEmail with props

Replace `defineEmail({ subject, text })` with the `subject` and `text` props of `EEmail`. `subject` is now required. Remove imports of `@lupinum/nuxt-email/define-email`.

### Remove ETailwind

Delete the `ETailwind` wrapper. Put Tailwind classes directly on elements and components inside `EEmail`.

### Move Tailwind configuration to tailwind.css

Move the `config`, `theme`, and `utility` props of `ETailwind` into `app/emails/tailwind.css`:

```css [app/emails/tailwind.css]
@theme {
  --color-brand: #00dc82;
}
```

Write custom utilities as `@utility` blocks. JavaScript Tailwind config and plugins are not supported.

### Remove style, custom and src blocks

Remove `<style>` blocks, custom blocks such as `<i18n>`, and `src=` blocks from templates and from the components they import. The build now fails on them in Nuxt too, with the file path in the message. Use Tailwind classes or inline styles, and import local components instead of `src=`.

### Write every class completely

The build reads class names from the source files. A class name built at run time, such as `` `bg-${color}-500` ``, is no longer resolved and stays in `class` unchanged. Write the full names:

```vue
<!-- Before -->
<EText :class="`text-${tone}-600`">Status</EText>

<!-- After -->
<EText :class="tone === 'red' ? 'text-red-600' : 'text-emerald-600'">Status</EText>
```

For a larger set of names, list them with [`@source inline()`]($docs/guides/tailwind#add-class-names-that-are-not-in-the-source) in `app/emails/tailwind.css`.

The [development preview]($docs/guides/preview-workflow) lists the classes that a render kept as written, and `createTestRenderer()` fails on them.

### Test with createTestRenderer

Replace `renderEmailComponent()` and `#nuxt-email/testing` with `createTestRenderer({ rootDir })` from `@lupinum/nuxt-email/testing`. It returns `renderEmail(name, props)`. This function fails when a render keeps a class without effect; [allow a class that must stay]($docs/guides/testing-your-emails#classes-without-effect-fail-the-test) with `allowUnknownClasses`. Pass the `codeBlock` option when templates use `ECodeBlock`. Pass the generated `EmailTemplateProps` type for typed names and props. See [Testing your emails]($docs/guides/testing-your-emails).

```ts
// Before
const email = await renderEmailComponent(Welcome, props)

// After
const { renderEmail } = await createTestRenderer({ rootDir: process.cwd() })
const email = await renderEmail('welcome', props)
```

You can remove `@vitejs/plugin-vue` from the test configuration if only these tests needed it.

### Compile standalone templates with the build helper

`@lupinum/nuxt-email/render` no longer exports `renderEmailComponent()`. Compile the email directory with `buildEmailRegistry()` from `@lupinum/nuxt-email/build` and call the `renderEmail(name, props)` of the generated registry. See [standalone rendering]($docs/guides/standalone-rendering).

### Install typescript and vue-tsc for the standalone build

Install `typescript` and `vue-tsc` in projects that call `@lupinum/nuxt-email/build`. They are now optional peer dependencies. Use TypeScript 5.9, the version that the package supports. A command without a version installs TypeScript 7, and the build then fails:

```bash
pnpm add -D typescript@~5.9.3 vue-tsc
```

### Install Shiki when you use ECodeBlock

The Shiki packages are now optional peer dependencies. If `nuxt.config.ts` sets `codeBlock`, install them in your application:

```bash
pnpm add @shikijs/core @shikijs/engine-javascript @shikijs/langs @shikijs/themes
```

Without them, module setup fails with this instruction. An application without `codeBlock` needs nothing.

### Add unplugin-vue if you used it

The package no longer depends on `unplugin-vue`. If your project imported it without listing it in its own `package.json`, add it to your dependencies.

### Pass EMarkdown content as source

`EMarkdown` no longer reads its default slot. Pass the Markdown string to the required `source` prop: replace `<EMarkdown>{{ body }}</EMarkdown>` with `<EMarkdown :source="body" />`.

### Remove unsafe URL schemes

`ELink` and `EButton` now reject an `href` with a `javascript:`, `vbscript:` or `data:` scheme. `EImg` rejects a `src` with a `javascript:` or `vbscript:` scheme. Such a render fails with an `EmailRenderError`.

### Remove the deleted error classes

Remove references to `DefineEmailOutsideRenderError`, `DuplicateEmailDefinitionError`, and `TailwindMissingHeadError`. `@lupinum/nuxt-email/errors` now exports only `EmailRenderError` and `UnknownEmailTemplateError`.

## Upgrade from 0.1.1

Apply these two changes, then follow the 1.0.0-beta.5 steps above:

- Style `ELink` color and text decoration explicitly when the design needs them. The component is visually neutral.
- Replace reads of `EmailRenderError.componentName` with `templateName`. No deprecated alias is provided.

## Migrate from React Email

Nuxt Email ports proven email-output behavior, not React's runtime or component API. Move a template by preserving its semantic document, replacing React components with the E-prefixed Vue primitives, and exposing it through Nuxt's generated server registry.

### The same email, two frameworks

#### React Email

```tsx
import { Body, Button, Container, Head, Heading, Html, Preview, Text } from '@react-email/components'

export function OrderEmail({ orderNumber, recipientName }: { orderNumber: number; recipientName: string }) {
  return (
    <Html lang="en">
      <Head><title>Order confirmation</title></Head>
      <Preview>Your order is ready.</Preview>
      <Body style={{ backgroundColor: '#f5f5f5', margin: 0 }}>
        <Container style={{ maxWidth: '600px', padding: '24px' }}>
          <Heading>Order {orderNumber} for {recipientName}</Heading>
          <Text>We have received your order.</Text>
          <Button href={`https://example.com/orders/${orderNumber}`} style={{ padding: '12px 20px' }}>
            View order
          </Button>
        </Container>
      </Body>
    </Html>
  )
}
```

#### Nuxt Email

Place the Vue version at `app/emails/order-confirmation.vue`:

```vue
<script setup lang="ts">
defineProps<{
  orderNumber: number
  recipientName: string
}>()
</script>

<template>
  <EEmail
    :subject="`Order ${orderNumber} confirmed`"
    lang="en"
    preview="Your order is ready."
    :style="{ backgroundColor: '#f5f5f5', margin: 0 }"
  >
    <template #head>
      <title>Order confirmation</title>
    </template>
    <EContainer :style="{ maxWidth: '600px', padding: '24px' }">
      <EHeading>Order {{ orderNumber }} for {{ recipientName }}</EHeading>
      <EText>We have received your order.</EText>
      <EButton :href="`https://example.com/orders/${orderNumber}`" :style="{ padding: '12px 20px' }">
        View order
      </EButton>
    </EContainer>
  </EEmail>
</template>
```

`EEmail` replaces `Html`, `Head`, `Body`, and `Preview`. Put the document title in the `head` slot. Vue SSR does not reproduce React 19's preview-title hoisting.

### Rendering

React Email renders an element directly and requests HTML and plain text separately:

```tsx
const html = await render(<OrderEmail {...props} />)
const text = await render(<OrderEmail {...props} />, { plainText: true })
```

Nuxt Email discovers the Vue single-file component (`.vue` file) as `order-confirmation`. It generates its prop type and returns both representations from one server renderer:

```ts [server/api/order-confirmation.get.ts]
export default defineEventHandler(() => {
  return renderEmail('order-confirmation', {
    orderNumber: 7319,
    recipientName: 'Ada',
  })
})
```

Do not import a component renderer into application code. The public path is the generated Nitro-only [`renderEmail`]($docs/reference/render-email) auto-import.

### Authoring translation

| React Email | Nuxt Email |
| --- | --- |
| JSX/TSX component | Vue `.vue` file under `app/emails/` |
| Imported `Html`, `Head`, `Body`, `Preview` | One `EEmail` root |
| Imported `Text`, `Button` | Registered `EText`, `EButton` |
| TypeScript function props | Standard Vue `defineProps<>()` |
| `children` | Default Vue slot |
| `{condition && <Text />}` | `<EText v-if="condition">` |
| `{items.map(item => <Text key={item.id} />)}` | `<EText v-for="item in items" :key="item.id">` |
| `style={{ backgroundColor: '#fff' }}` | `:style="{ backgroundColor: '#fff' }"` |
| `<Tailwind>` wrapper | No wrapper; classes work everywhere ([Using Tailwind]($docs/guides/tailwind)) |
| Renderer receives an element | Renderer receives a generated template name and typed props |
| Preview-specific React app | Exact sibling fixture plus development-only `/__email` |

Use Vue's native attribute names and CSS styles. React-shaped convenience props such as `mx` are intentionally absent — use ordinary CSS in `style`.

Nuxt Email uses Tailwind v4 at build time. It does not inherit your Nuxt stylesheet or browser CSS variables. Put concrete tokens in `app/emails/tailwind.css` when migrating custom utilities such as `text-primary`. A React Email `pixelBasedPreset` is not needed, because the build always writes sizes in `px`. A JavaScript config has no equivalent; write the values as `@theme` tokens.

### Behavioral differences to review

- Compatibility is tracked **per behavior**, never as a global React Email compatibility claim.
- Component names and the authoring API are Vue-native and E-prefixed.
- React streaming, Suspense behavior, generated React markers, JSX execution, and the React preview stack are not ported.
- Some document, preview, and table-marker output intentionally differs where Vue authoring or email safety requires it.

Do not use this summary as a parity matrix. Test the templates you migrate.

### Sending remains application-owned

Nuxt Email stops at `{ html, text, subject }`. Keep recipients, sender identity, credentials, attachments, tags, scheduling, and delivery policy in your provider SDK. Nuxt Email has no provider-neutral adapter or public send endpoint. You can keep provider-specific features and set the subject beside the template with the [`subject` prop]($docs/guides/subject-lines).
