Nuxt Email separates automated compatibility evidence from manual client results.

## What is automatically proven

The Tailwind-to-inline-style conversion and several components are adapted from React Email. Golden files in the repository pin the rendered HTML of presentation tables, Outlook-specific button spacers, preview hiding, font declarations, and Tailwind output. A change to that output fails the tests until a maintainer reviews it.

A second test checks the generated CSS of every utility in a fixed matrix of Tailwind classes. It fails when the output contains syntax that is not email-safe, such as `rem`, `oklch()`, nesting, or a logical property. Three known exceptions are listed in [Using Tailwind]($docs/guides/tailwind#limits).

Golden files prove that the output stays the same. The CSS test proves that the output avoids the syntax it checks for. Neither test opens an email client, so they do not prove that every email client displays a message identically.

## Beta smoke test

Matthias completed the owner-run `1.0.0-beta.1` smoke test on 2026-08-22. The same `proof-kit` message passed in Gmail web, Apple Mail on macOS, and Outlook classic on Windows in light and dark modes. The [signed QA record](https://github.com/lupinum-dev/nuxt-email/blob/main/docs/release/client-qa-checklist.md#100-beta1-smoke-test) records the tested commit and artifact hashes.

`1.0.0-beta.6` replaced the renderer. The smoke test is not complete for the new renderer. `1.0.0-beta.6` was released without it. After the release, its output passed a check in Apple Mail on macOS in light mode, with one defect that `1.0.0-beta.7` corrects. No email client displayed the output of `1.0.0-beta.7` before its release. The [QA record](https://github.com/lupinum-dev/nuxt-email/blob/main/docs/release/client-qa-checklist.md) lists the open clients.

The full eight-client checklist required for stable `1.0.0` is also not complete. An external transactional beta remains pending.

## Test your emails in real clients

Automated tests do not open real email clients. Before you send a new or changed template to recipients, check it in the clients that your recipients use.

::steps
### Render the template
Render the template with `renderEmail` and the props of a real message.

### Send it to test mailboxes
Send the rendered `subject`, `html` and `text` to your own test mailboxes through your delivery client. Nuxt Email does not send mail.

### Open it in the clients
Open the message in the clients that your recipients use, in light and dark modes. **Gmail web**, **Apple Mail** and **Outlook classic** on Windows use three different rendering engines, so check at least these three.

### Record the result
Note client versions, screenshots and defects.
::

The maintainers run the same procedure with one fixed message before a release. The [QA record](https://github.com/lupinum-dev/nuxt-email/blob/main/docs/release/client-qa-checklist.md) lists its clients and checks.

## What to check

- Inbox preview shows only the intended preview sentence and does not expose filler characters.
- A remote image has useful alternative text when images are blocked.
- Heading, paragraphs, divider, and footer links retain readable spacing.
- A button is clickable and has comparable horizontal and vertical padding **in Outlook**.
- Two columns stay in one row at desktop email widths and remain readable when the client narrows the message.
- Link destinations and the `mailto:` link are correct.
- Plain-text fallback contains the meaningful content and destinations but excludes preview filler and images.
- No script, hydration payload, framework state, or event-handler attribute is present.
- Text that uses a Tailwind font family utility, such as `font-sans`, uses the intended font. The build writes multi-word family names such as `Segoe UI` without quotes.
