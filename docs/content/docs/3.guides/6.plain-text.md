---
title: Plain text
description: How the plain-text fallback is produced from the rendered HTML, what it excludes, and how to control table output.
---

Every render returns a `text` string alongside `html`. By default it is a deterministic fallback produced from the **final rendered HTML**. Nuxt Email uses a fixed `html-to-text` version with no line wrapping.

When automatic conversion is not good enough, pass the `text` prop to `EEmail`. Authored text replaces derivation for that render. It does not create a second template or rendering path.

```vue [app/emails/welcome.vue]
<script setup lang="ts">
defineProps<{ name: string, actionUrl: string }>()
</script>

<template>
  <EEmail subject="Welcome" lang="en" :text="`Welcome, ${name}. Open your dashboard: ${actionUrl}`">
    <EText>Welcome, {{ name }}.</EText>
  </EEmail>
</template>
```

## What plain text includes and excludes

- **Excluded:** head content, images, `<script>`/`<style>` content, and any element marked `data-skip-in-text="true"`. The `preview` text of `EEmail` is therefore absent from the fallback.
- **Links:** destinations are retained when the visible text differs from the URL. Fragment links and `mailto:` links follow React Email's behavior.
- **Structure:** nested lists, ordered-list starts, blockquotes, hard breaks, preformatted content, Unicode, and ordinary tables are pinned by golden-file tests.

## Controlling table output

By default, the conversion joins the text of table cells without a separator. Two cells with the text `Left` and `Right` give `LeftRight`. A block element inside a cell, such as `EText`, starts on its own line. When you need aligned columns for a table, add `data-text-format="dataTable"` to that table:

```vue
<table data-text-format="dataTable">
  <!-- rows -->
</table>
```

## Inspect it every time

Plain text is a real deliverable that some recipients and spam filters read. Inspect it in the [development preview]($docs/guides/preview-workflow)'s **Plain text** tab for every transactional template, exactly as you would review the HTML.

::card{title="ECodeInline appears once" icon="lucide:info"}
`ECodeInline` keeps two copies in HTML for `Orange.fr` compatibility, but marks the hidden copy to be skipped by plain-text generation. Recipients therefore receive the code once in the text alternative. This is an intentional divergence from React Email.
::
