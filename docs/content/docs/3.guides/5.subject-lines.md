---
title: Subject lines
description: Set the subject with the EEmail subject prop from the same typed props, and read it back from the render result.
---

Nuxt Email does not send email, but a template often knows how to phrase its own subject from the same data it renders. Set it with the `subject` prop of `EEmail`.

## Set a subject

```vue [app/emails/welcome.vue]
<script setup lang="ts">
defineProps<{ name: string, actionUrl: string }>()
</script>

<template>
  <EEmail :subject="`Welcome, ${name}`" lang="en">
    <EHeading>Welcome, {{ name }}</EHeading>
    <EButton :href="actionUrl" class="px-5 py-3">Open dashboard</EButton>
  </EEmail>
</template>
```

`subject` is a required string. Use a template expression, a constant, or a `computed` value from `<script setup>`.

## Read it back

Every render result carries the subject:

```ts [server/api/welcome.get.ts]
export default defineEventHandler(async () => {
  const { html, text, subject } = await renderEmail('welcome', {
    name: 'Ada',
    actionUrl: 'https://example.com/dashboard',
  })

  // subject === 'Welcome, Ada'
  return { html, text, subject }
})
```

`subject` is a `string` on `RenderedEmail`. It is not written into the HTML. Add a `<title>` in the `head` slot of `EEmail` if you also want one there.

## Rules

- **A non-string subject fails the render** with an `EmailRenderError` whose cause explains the value.
- **Concurrent renders are isolated.** Each render has its own state, so subjects never leak between simultaneous renders.

::card{title="You still pass it to your provider" icon="lucide:info"}
`subject` keeps the subject phrasing beside the template. You still hand it to your provider SDK with `from`, `to`, `html`, and `text`. Nuxt Email does not send mail or set headers.
::

Continue with the [sending guide]($docs/guides/sending-email) for a complete provider handoff.
