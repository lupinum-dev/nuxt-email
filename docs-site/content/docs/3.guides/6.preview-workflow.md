title: Preview workflow
description: Use the development-only /__email preview, add fixtures, and keep messages within the Gmail clipping budget.
---

Nuxt Email exposes `/__email` while the Nuxt development server is running. It lists every template discovered under `app/emails/`, marks templates without fixture data, and shows the selected template as rendered HTML, exact HTML source, or plain text. It polls the development endpoints once per second, so saved template and fixture changes appear without restarting Nuxt.

The preview calls the same server-only registry and `renderEmail()` implementation your handlers use. It is a rendering and debugging tool — not a second rendering path and not an email-client compatibility guarantee.

## Add a fixture

Place one exact sibling file beside a template. Only the `.fixtures.ts` suffix is recognized, and it must default-export one props object:

```ts [app/emails/welcome.fixtures.ts]
import type WelcomeEmail from './welcome.vue'

type WelcomeEmailProps = Omit<
  InstanceType<typeof WelcomeEmail>['$props'],
  keyof import('vue').PublicProps
>

export default {
  firstName: 'Ada',
  activationUrl: 'https://example.com/activate',
} satisfies WelcomeEmailProps
```

v0.1 intentionally supports **one fixed scenario per template** and does not accept request-provided props or generate editing forms.

## Inspect output

::steps
### Preview
Loads the raw rendered HTML in a sandboxed iframe (no script permission).

### HTML
Displays the exact `html` returned by `renderEmail()`.

### Plain text
Displays the exact `text` returned by `renderEmail()`.

### Copy / Open
**Copy** copies the active representation; **Open** opens the raw development render in a separate tab.
::

Render failures show the template name, the wrapped `EmailRenderError` stack, and its original cause. A template without a fixture stays visible in the list but cannot be rendered until its sibling fixture is added.

## Mind the Gmail clipping budget

Gmail clips a message once its HTML exceeds roughly **102 KB**, hiding everything past that point behind a "[Message clipped] View entire message" link — which frequently truncates the unsubscribe footer and tracking. Because Nuxt Email output is deterministic, you can measure it precisely:

```ts
const { html } = await renderEmail('welcome', props)
console.log('bytes:', Buffer.byteLength(html, 'utf8'))
```

Keep the rendered HTML comfortably under 102 KB. Inlined Tailwind utilities and repeated markup add up quickly, so measure your largest, most dynamic template.

## Production boundary

The preview page, list endpoint, render endpoint, and fixture imports are registered **only in development**. Production builds contain none of their routes or fixture data. The raw render endpoint uses a restrictive content security policy, and the page iframe is sandboxed without script permission. The development endpoints are deliberately not configurable production render or send APIs — use the typed server-only [`renderEmail`]($docs/reference/render-email) in your handlers.
