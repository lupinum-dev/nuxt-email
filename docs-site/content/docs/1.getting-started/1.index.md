Nuxt Email is a Nuxt module for authoring transactional emails as ordinary Vue single-file components and rendering deterministic HTML and plain text from Nitro server code. You write `.vue` files; the module discovers them, generates typed render calls, and produces email-client-safe output.

It does one job and stops there. Nuxt Email does not send mail, choose providers, manage recipients, or own subjects beyond exposing one you compute. You hand the rendered `html` and `text` to your provider SDK.

## Why the output is trustworthy

Email HTML is unforgiving: clients strip `<style>`, break flexbox, and mangle padding. Nuxt Email's value is not the authoring syntax — it is that the output has been proven to match a renderer that already survives real inboxes.

- **Checked against React Email.** Every email-safety behavior is compared, case by case, to a pinned [React Email](https://react.email) oracle (version `6.9.0`, `@react-email/render` `2.1.0`). The [conformance report]($docs/reference/conformance) is generated from that comparison and is the source of truth for supported behavior and intentional divergences.
- **Deterministic.** Two renders of the same template and props return byte-identical HTML and a matching plain-text fallback. No IDs, timestamps, hydration payload, or mutable renderer state.
- **Server-only and typed.** `renderEmail('welcome', props)` is generated from your `app/emails/` folder. Unknown template names, missing props, and wrong types fail at compile time.
- **Honest about limits.** No global "React Email compatible" claim is made. Divergences are documented per behavior. See the [conformance report]($docs/reference/conformance) and the [migration guide]($docs/reference/migration).

## Release status

`0.1.0` is the current release candidate, not an approved public release. The working package name is `nuxt-email`; npm name ownership and publishing access are still being confirmed. Final publication is also gated on manual client checks in Gmail web, Apple Mail, and Outlook for Windows, and on an external transactional-email beta. Until those close, use only the exact candidate tarball and SHA-256 named in the release record.

## Supported environment

- **Node.js** `^22.12.0 || ^24.11.0` — Node 22 from 22.12 onward, or Node 24 from 24.11 onward.
- **Nuxt** `^4.4.8` — Nuxt 4.4.8 or a later Nuxt 4 release.
- **Vue** `^3.5.0`.

Node 20/23/25, Nuxt 3, Nuxt 5, edge runtimes, and client-side email rendering are outside the v0.1 support contract.
